## 1. 用户目标与修正

在 Windows 本地实现研究工作台，核心业务与界面兼容 macOS。研究执行器为 GitHub Copilot CLI，使用其原生 /research 完成调查。模型推理由用户授权的 ChatGPT 订阅提供。

此前将研究执行器改为 Codex app-server，是对用户意图的错误理解。本版按照“Copilot 执行研究、ChatGPT 订阅提供模型”的分工修订。之前的独立审阅针对 Codex 草案，本版另行审查。

分享会话是功能与流程参考。起始工作区为空，原源码、数据库和界面资源尚未获得，原环境的成功记录需要在 Windows 重新验证。

## 2. 已确认的产品方案

采用本地 Web 工作台，React + TypeScript 前端、Node.js + TypeScript 后端、SQLite。单机单用户，服务监听回环地址。

此前比较过 Electron 桌面应用及 Python 后端方案。用户选择本地 Web 方案，便于跨平台共享界面与业务。依赖版本、组件库及内部接口命名交由实施阶段确定。

## 3. 研究执行与订阅接入

拟验证的链路为

浏览器工作台 → 后台作业 runner → Copilot CLI 原生 /research → 本地订阅适配服务 → OpenAI Responses API

工作台负责配置、任务和报告管理。Copilot 负责研究编排、工具执行及研究报告。订阅适配服务负责官方登录、令牌刷新及必要的协议适配。

### 3.1 已有官方依据

- Copilot /research 会调用专用研究 Agent，支持本地代码、GitHub 与网页资料，输出带引用的 Markdown 报告。
- Copilot 自定义 provider 支持 Responses API、Bearer Token、自定义请求头和模型配置。
- OpenAI Sign in with ChatGPT 提供本地或开源应用申请使用用户 ChatGPT 计划的官方流程，获得相应授权后可调用指定模型的 Responses API。
- Copilot 配置中的 bearerToken 是静态值。长任务的令牌刷新需要应用或 SDK 层处理。
- ChatGPT 计划接入对请求字段、历史传递和工具格式存在明确要求。

以上依据证明了两端的接口条件，端到端组合的可用性尚待验证。

### 3.2 官方登录与凭据

本节是自行实现官方授权接入的候选设计。2026-11-06 的进一步检索找到已有 CLIProxyAPI 转接方案，第一阶段优先验证该现成组件。最终接入选型根据真实 /research 验证确定。

工作台提供 Continue with ChatGPT，用户在官方浏览器页面登录并授权应用使用其 ChatGPT 计划。应用采用官方动态客户端注册、PKCE、state、nonce 和本地回调流程，持久保存主机标识及账号对应的客户端注册。

首版设计为一个活动 ChatGPT 账号，可重新登录切换账号。任务记录账号、工作区、请求模型和实际返回模型。账号切换要求所有作业静止，恢复会话时核对账号和工作区。

应用的访问令牌与刷新令牌保存在当前用户的系统凭据存储，SQLite 保存引用和元数据。适配服务在请求前刷新令牌并串行化刷新，处理轮换和失效。日志与导出过滤凭据字段。

### 3.3 模型和订阅权益

2026-11-06 补充确认，页面提供模型和推理等级选择。执行设置保存默认值，模板、课题与启动表单可覆盖；模型切换联动合法推理等级，后端复核，运行详情保存并显示本轮快照。实际模型请求记录用户选择、Copilot 请求值与上游返回值，保证页面配置可以验证。

使用官方授权令牌读取当前账号可展示的模型目录，以真实推理请求核验访问权限。模板保存模型与支持的推理强度，任务启动冻结配置快照。用量与额度按官方返回信息展示，缺失字段显示未知。

Copilot 官方研究文档说明研究 Agent 使用独立配置模型，主会话 /model 选择未必作用于研究 Agent。验证必须覆盖研究主代理和子代理，记录实际 provider、模型和请求路径，核对订阅用量来源。

### 3.4 本地适配服务

优先保留 Responses 协议，使用回环地址和逐次运行的本地认证。适配服务持有 OpenAI 令牌，Copilot 持有本地连接凭据。

按官方规范设置 store=false、stream=true，处理上下文 input、instructions、支持的工具定义、流式文本、工具调用、终止事件和错误。针对不支持的参数做显式校验或可解释的兼容转换。影响语义的功能缺口返回具体错误。

用户授权的任务上下文经该链路发送至 OpenAI。研究与工具循环由 Copilot 承载，适配服务承担模型连接与协议处理。

如果组合验证出现问题，先定位到登录、模型接口、研究路由或工具能力，向用户报告实测证据，再调整方案。

## 6. 后台、数据和文件

后台服务管理独立 runner，runner 承载 Copilot 和本次订阅连接。runner 保存事件、日志和心跳，浏览器关闭后继续执行。Web 服务重启后重新连接 runner，runner 丢失时标记运行中断并提供恢复。

SQLite 主要实体为账号引用、模板、课题、任务、运行、产出物、目录、标签、候选作业及候选项。task 可有多次 run，续写追加运行记录，冻结每次配置、日志、会话 ID 和模型信息。

SQLite 使用外键、WAL、busy timeout、事务与条件状态更新。课题启动、运行派发及候选保存使用幂等标识。同一会话使用唯一活动租约防止并发续写。默认研究并发 1，候选生成共享账号并发预算。

每次运行目录划分 config、logs、materials、deliverables。只登记约定交付位置或经校验的交付清单。下载源码和研究资料保存在 materials。

产出物使用稳定 ID，文章一级标题决定默认展示及下载名，用户手动名称独立保存。兼容 Windows 非法字符、保留名、重名与长度规则。文件访问校验规范化路径及符号链接最终位置。

数据库迁移前备份。涉及文件和数据库的移动有可恢复操作记录。跨平台数据包使用相对路径，项目路径重新绑定，账号在目标机器授权，Copilot 会话恢复按导入结果检测。

## 7. 生命周期与自动收尾

状态为 queued、starting、running、waiting_input、finalizing、completed、failed、stopped、interrupted，界面显示原因。

启动前检查登录、模型、Copilot 能力、权限和目录。研究完成判定结合主会话本轮结束、子代理结束、报告正文落盘及 CLI 正常收尾。优先使用 Copilot 可验证事件，具体事件或会话日志接口在第一阶段锁定。

原生研究的交互模式由 runner 承载，满足完成条件后自动退出。会话和中间材料保留供续写。只有提问、提纲或正文缺失时显示交付未达标与继续完善操作。

停止采用先优雅终止、后处理所属进程树的流程，核对进程身份以防 PID 复用。模型或网络错误记录实际原因，重试采用有上限的退避。默认运行预算 60 分钟，可配置，超时保留已产生材料及结束原因。

权限预设为限定授权和完全授权，首次配置由用户选择，模板可继承。Copilot 参数以目标版本验证为准。待人工输入时提供实时终端和原因。

## 8. Windows 与 macOS

2026-11-06 安装 Copilot CLI 1.0.106 和 CLIProxyAPI 8.0.57 至项目 .local-tools，测试数据位于 .local-state，两目录均已加入 .gitignore。Copilot 自身运行组件还会解压至系统用户缓存。

网页登录使用 --codex-login 的 Codex OAuth 流程成功完成，独立凭据目录已有记录。实际登录过程遇到直连认证服务 HTTP 403，配置使用电脑现有的 http://127.0.0.1:7890 代理后成功。该结果验证的是 CLIProxyAPI 的 Codex OAuth 路径，前文官方 SIWC 方案仍是另一条候选路径。

Copilot 通过同一接口以 BYOK 模式请求 gpt-6-luna，返回 COPILOT_SUBSCRIPTION_OK，进程退出码 0。该次 Copilot 请求报告输入 13,098 token、输出 11 token。实际扣减的订阅额度百分比尚无观测结果。原生 /research、子代理路由、长任务刷新和续写尚待验证。
